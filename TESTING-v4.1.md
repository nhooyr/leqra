# leqra v4.1 verification

See **TEST-NOTES-v4.1.md** for exact results, coverage and the failed synthetic
jitter comparison. Current reports are version-labelled in `tests/results/`.
The previous release's test document is preserved as **TESTING-v4.0.md**.

## Results actually observed

415 top-level Go tests passed with the race detector (800 including subtests),
with two opt-in tests skipped. 29 JavaScript networking tests, 146 production
HTTP/WebSocket assertions and 121 browser assertions passed. Go vet, syntax,
the compiled server and its eight version/asset/fixture checks passed.

**Two v4.1 synthetic-jitter runs failed their unchanged thresholds.** The original
v4.0 server/assets also failed a sequential control run. None is counted as a
passing smoothing regression. The separate live Ghost/Cannon reconnection and
matchmaking/browser transfer tests passed. Read the recorded limitation instead
of treating historical passing reports as new executions.

## Repeat core checks

```sh
go test -race -count=1 ./...
go vet ./...
node --check web/game.js
node --check web/netcode.js
node --test tests/netcode.test.cjs
go build -trimpath -o leqra .
```

The shared movement fixtures can be regenerated intentionally:

```sh
LEQRA_PHASE_PARITY=tests/fixtures/phase41.json \
  go test -run '^Test41WriteMovementParity$' -count=1
```

`phase41_test.go` defines the opt-in generator's environment variable; the normal
suite does not rewrite files. The delivered fixtures were generated by Go and
checked in Node and the browser. Test-only helpers are not compiled into a normal
`go build` executable.

## Production protocol checks

Run a production server in another terminal. These tests create temporary rooms
and matches on that server and require the optional Python `websockets` package:

```sh
python tests/matchmaking_protocol.py http://127.0.0.1:8080 \
  --expect-version 4.1.0 --output matchmaking-v4.1.json
python tests/phase41_protocol.py http://127.0.0.1:8080
```

The first verifies all six queue modes, complete human lineups, party consent,
room transfer and return, host restrictions, room isolation and reconnect handoff.
The second verifies ten pickups/defaults, Ghost filtering/spawns, server-owned
power state, host-only rules and production exclusion of test endpoints.

## Optional browser checks

Install Python `playwright` and `websockets` and provide Chromium. These are test
utilities, not game runtime dependencies. The new feature harness uses
`/usr/bin/chromium`; adjust that test path for another installation.

Start the isolated loopback test fixture in another terminal:

```sh
LEQRA_BROWSER_FIXTURE=1 LEQRA_BROWSER_ADDR=127.0.0.1:18041 \
  go test -run '^TestBrowserFixture$' -count=1 -timeout=0
```

Then run:

```sh
python tests/phase41_browser.py --url http://127.0.0.1:18041 \
  --output test-output/phase41
python tests/matchmaking_browser.py http://127.0.0.1:18041 \
  --output test-output/matchmaking41
python tests/network_smoothing.py http://127.0.0.1:18041 --isolated \
  --browser /usr/bin/chromium --profile jitter --local2 --roles \
  --output test-output/network41
```

The final command is the stress check that failed in the delivered runs; it is
included for reproducibility, not claimed as passing. The first suite performs
local deterministic controls plus real online host/P2/spectator controls, actual
pickup collection, cannon bounces, Ghost expiry and reconnection. Its injected
fixture grants are explicitly disclosed in the result notes.

Tests use desktop and phone emulation, not physical devices or public hosting.
The v4.1 network module changes are limited to Ghost movement/expiry prediction
and remote interpolation; no change to simulation/snapshot rates is intended.
